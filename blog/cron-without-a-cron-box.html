Cron without a cron box

Recurring jobs usually mean one more process to babysit. In Cosmonats, a schedule is just a message parked in NATS — and NATS keeps the time.

The bitsbeam crew mission control, earth

Every app grows a few jobs that run on a clock: the nightly report, the weekday digest, the hourly cleanup. The usual answer is a separate scheduler process — followed by a debate about which box runs it, and what happens when that box goes dark.

A schedule is just a message

Since NATS Server 2.14, a stream can hold scheduled messages. Cosmonats parks every cron entry in a dedicated scheduled stream. NATS fires it on the cron expression, and a worker's scheduler dispatches the job onward — the same path a delayed job already takes.

Crew note

Whatever's in NATS is exactly what runs — and exactly what you see in the web UI.

Declare it next to your streams

Run cosmo -C config/cosmo.yml -S and it syncs — whatever's in the file is what ends up scheduled, the same way streams are set up. Five-field UNIX cron is normalized for you; @-shortcuts pass straight through.

One thing to remember

Cron firings are dispatched by the scheduler, so keep at least one worker running without --no-scheduler. That's the whole checklist — no extra box, no leader election, no second config.
