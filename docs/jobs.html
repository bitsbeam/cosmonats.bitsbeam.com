Core concepts

Jobs

perform_bulk publishes a thousand jobs at a time without waiting on each ack, which is many times faster than calling perform_async in a loop. It takes the same options (perform_bulk(list, in: 60), set(...).perform_bulk), joins the current batch, and returns the jids in order. When the stream refuses some jobs, e.g. a full discard: new stream, it raises Cosmo::BulkEnqueueError: its jids are nil for the jobs that weren’t enqueued, errors says why by index, and the chunks after the failing one aren’t published. Inside a batch, the refused jobs never join it, so rescue within jobs to resend them while the batch is still open:

An error that is a NATS::Timeout means no ack came back, not that the job wasn’t stored, so resending it can run that job twice.

Inside perform, the job instance knows about the message it came from:

Accessor Value
jid Job id, returned by perform_async
attempt 1-based delivery attempt
enqueued_at Time the job was enqueued; for a cron job, when NATS fired the schedule
scheduled_by Subject of the cron schedule that fired the job, nil for jobs enqueued any other way
batch_id Id of the batch the job belongs to, nil outside a batch
